## 1. 项目现状速览

- **项目**：砚台考研打卡 —— 考研学习管理网站，个人本地使用（目标用户 1 人）。React 18 + TS + Vite（client/）、Express 4 + TS（server/）、MySQL 8（server/）、Zod 共享校验（shared/）。
- **运行**：`npm run dev`（client 5173 + server 3001）；测试 `npx vitest run`（node 环境，**无 IndexedDB、无 jsdom**）；`npm run build`、`npm run lint`。
- **已完成**：账号系统（邮箱+密码，会话存 MySQL）、任务/预设/番茄钟/网课/统计（森林/热力图）/复盘；landing 介绍页；**P1 导出**（Profile 下拉「导出数据」→ `yantai-backup-*.json`，格式定稿 `format: "kaoyandaily-backup"`, `schemaVersion: 1`）；**P2 导入**（未登录建号+自动登录；已登录差异预览 + 覆盖/合并，先删后插防跨账号串号）。

### 前端 API 层现状（P3 改造对象）

- 8 个模块：`client/src/api/{tasks,presets,focus,courses,reviews,statistics,settings,auth}.ts` + `client/src/api/client.ts`（统一 fetch：`api.get/post/put/patch/delete/download`，204 处理，401 全局登出回调）+ `client/src/api/backup.ts`（exportData/previewImport/importData）。

## 2. P3 需求定义（对齐稿定稿，勿擅自变更）

1. 登录页新增「**本地模式**」入口。
2. 本地模式数据**全部存浏览器 IndexedDB**，与服务器（MySQL）互不干扰；通过 P1/P2 的导出文件互通。
3. 进入本地模式 → **本地账户管理**：选择已有本地账户（点击即进入，**无密码**）/ 新建本地账户 / 从备份文件导入账户。
4. 进入本地账户后：**所有页面功能与服务器模式一致**（任务/预设/番茄钟/网课/统计/复盘全可用），数据读写走 IndexedDB；统计（森林/热力图/今日摘要）在前端等价实现。
5. 已登录本地账户也可「导出数据」（生成同格式文件）。
6. 用户已拍板：本地账户**选择即进入无密码**；导出文件**不加密**。

**边界外**：不改服务器端；不做本地模式的服务器同步；不要求离线 PWA。

## 3. 关键设计决策（已定稿，实现时遵守）

- **存储**：**单个 IndexedDB 库** `kaoyandaily_local`，stores：`accounts`（本地账户）+ 8 个业务 store（presets/tasks/reviews/courses/episodes/focusSessions/studyRecords/settings）+ `meta`（库版本/升级用）。每条业务记录**用 `index('accountId')` 索引**该记录归属的本地账户；查询一律先按 accountId 过滤（**user_id 概念本地化为 accountId**，绝不复用服务器 user_id）。
- **本地账户模型**：`accounts` 记录 `{ accountId(uuid), email, createdAt }`；当前激活账户 id 存 `localStorage['kaoyandaily_local_activeAccount']`。新建本地账户时 email 可任意填（本地唯一即可）；导入账户用文件中的 email。
- **本地 ID**：沿用备份格式的 UUID id（本地直接复用，冲突只可能是重复导入——本地无全局跨账户主键约束，按 accountId 过滤即可避免串号；导入合并时同 id 同日期做先删后插，参考 P2）。`daily_reviews` 在本地用 **index('accountId_reviewDate')** 模拟唯一键。
- **双后端抽象**：新增 `client/src/local/` 层，提供 `LocalDataStore`（实现与 8 个 `xxxApi` **同名同签名**的方法）。每个 `xxxApi` 方法内部先判断数据模式：
  ```ts
  // 例（tasks.ts）
  import { isLocalMode } from '../local/mode';
  export const tasksApi = {
    getByDate: (date) => isLocalMode() ? localStore.tasks.getByDate(date) : api.get<Task[]>(`/tasks?date=${date}`),
    ...
  };
  ```
  模式开关：`client/src/local/mode.ts` 的模块级变量 + `setLocalMode(bool)`；页面后续可改用 `useDataMode()` hook 订阅切换。**目标：业务页面组件改动尽量少**。
- **统计**：forest / heatmap / today-summary 的**计算逻辑从服务端 SQL 移植到前端纯函数** `client/src/utils/localStatistics.ts`（§6 给逐一对照）。
- **凭证/会话**：本地模式**无密码**；`useAuth` 需扩展为「服务器会话已登录 **或** 本地账户已激活」即视为登录。`useAuth().user` 在本地模式下返回 `{ id: activeLocalAccount.accountId, email }`，登出本地账户 = 清 activeLocalAccount。
- **番茄钟**：`useFocusSession` 写会话/记录的调用点替换为通过 `focusApi`/本地 store（保持 hooks 不变）。
- **导入/导出本地分支**：`backupApi.exportData` 在本地模式从 IndexedDB 组装 BackupFile（复用 §1 格式）；本地导入的 preview（差异）用前端计算的 `computeDiff`（可把 P2 服务端 `server/src/utils/import.ts` 的 `computeDiffCounts`/`computeDiffSummary` 逻辑移植成前端纯函数，依赖去掉 mysql 语义即可）。ImportBackupModal（已存在 `client/src/components/ui/ImportBackupModal.tsx`）尽量复用，差异预览走本地实现。

## 6. 统计移植要点（对照 server/src/routes/statistics.ts）

三接口全部基于 **study_records**（明细）聚合：
1. **forest**（`GET /api/v1/statistics/forest?mode=day|week|month&date`）：
   - 范围：mode=day → 当日；week → 当周（周一 0 点到周日）；month → 当月。范围算法用本地日期。
   - 数据源：`study_records WHERE created_at >= rangeStart AND < rangeEnd`，**默认 source 过滤：`focus_session` 全部；`course_video` 且 `focus_session_id IS NULL` 才计（去重）**。
   - 统计：totalFocusSeconds、totalCompletedSessions（focusSessions 表统计 completed）、按 subject 分组（math/english/408/free）的秒数与树数（树 = 满 3600 秒一棵，按科目独立）。
   - 返回结构见 `shared/src/schemas/statistics.ts`（ForestResponseSchema）。移植后**字段名/形状逐一对照**。
2. **today-summary**：今日（本地日期）的专注秒数、完成会话数、任务未完成数（daily_tasks）、预设数等（看 schema/路由原文）。
3. **heatmap**：近约 365 天每日专注秒数（`HeatmapResponseSchema`，date→seconds 数组）。
- 移植后建议抽纯函数，输入为「该账户的 studyRecords/focusSessions/tasks 全量（或按日期截取）数组」，输出与服务器响应同构，**用单测锁定与服务器对同数据计算一致**。

## 7. 风险与坑（项目历史教训，务必遵守）

1. **项目工作流是硬约束**（§8）：任何代码修改都走 10 步流程，用户确认后才动手；**先复述对齐**再实现；**用户下令前不 commit/merge/push**。
2. **红线**：修改已有文件前先 Read；颜色只用 `var(--color-xxx)`（tokens.css）；动效只 transform/opacity + `useReducedMotion` 门控；**勿动 `client/vite.config.ts` 的 manualChunks**；`user_id` 永不客户端传入（本地用 accountId 概念，不含服务器 user_id）。
3. **framer-motion 已锁 11.18.2，禁止升级**（12 有回归会静默坏掉滚动动效）；**改依赖/配置后必须重启 vite dev**（`.vite/deps` 缓存坑）。
4. **Modal** 已改为 portal 到 body（`Modal.tsx`）；别在含 `backdrop-filter` 祖先内放 fixed 元素（顶栏 glass-2 会劫持 fixed 定位）。
5. **测试环境是 node**：无 IndexedDB/DOM。要么用 **fake-indexeddb**（需用户批准一个新 devDependency），要么本地模式逻辑走「手动 Playwright 脚本照**真实浏览器**验证」。**不要**尝试在 vitest 里 mock 整套 IndexedDB（太脆）。
6. **IndexedDB 版本升级**：改 schema 必须升 version 并在 `onupgradeneeded` 里建 store/索引；旧库迁移要处理（当前无存量本地库，可宽松）。
7. **多账户数据隔离**：所有 store 查询/写入必须先按 `accountId` 过滤；删除账户 = 删除该 accountId 全部记录（遍历 store）。
8. **番茄钟计时**：完成会话才写 focusSessions+studyRecords；取消写 status=cancelled 的 focusSessions（对照 `server/src/routes/focus.ts` 语义）；网课打勾**不写 study_records**（历史决策 8467b8c）。
9. **日期**：所有日期字符串 YYYY-MM-DD（本地日期，勿用 UTC 换算）；created_at/updated_at DATETIME 字符串保持导出格式一致（对照 `server/src/utils/date.ts`、`client/src/utils/date.ts`）。
10. **限流服务器 import 1h5 次**：本地模式不需限流；但手测时若碰到 429 是服务器端限流，用 `touch server/src/index.ts`（tsx watch 重载）重置。
