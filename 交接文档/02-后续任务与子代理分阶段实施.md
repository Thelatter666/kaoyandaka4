# 02 后续任务与子代理分阶段实施

> 总目标：将「砚台考研打卡」作为**完全公开的产品**上线（任何人可注册使用，数据互相隔离）。
> 本文档是实施依据；主对话负责协调与验收，**每个 T 任务派发一个子代理执行**。

## 全局结构

- **阶段 0（用户人工，与开发并行，不占开发排期）**：购买国内轻量云服务器（2核2G）+ 域名 + 提交 ICP 备案（周期 1-3 周）
- **阶段 2（开发主体，约占 60%）**：账号系统 + 数据隔离 —— 上线阻塞级
- **阶段 3（部署）**：服务器环境 + 发布 + 收尾

## 阶段 2：账号系统 + 数据隔离

### T2.1 数据库：users 表与迁移
- 内容：`users` 表（id / username 或 email / password_hash / created_at）；既有业务表（courses / tasks / presets / focus_sessions / reviews 等）全部加 `user_id` 外键 + 索引；编写迁移 SQL（`server/src/db/schema.sql` 与迁移脚本），本地库执行验证
- 必读：`server/src/db/schema.sql`、`server/src/db/init.ts`
- 验收：迁移后表结构正确；旧数据挂到一个种子用户下；回滚方案可行

### T2.2 认证 API
- 内容：`POST /api/v1/auth/register`、`POST /api/v1/auth/login`、`GET /api/v1/auth/me`、`POST /api/v1/auth/logout`；密码哈希（bcrypt 或 argon2，禁明文/MD5/SHA1）；会话方案（JWT httpOnly cookie 或 express-session，二选一并在任务书中说明理由）；共享 Zod 校验放 `shared/src/schemas/`
- 必读：`server/src/routes/`（任一路由看风格）、`server/src/middleware/validate.ts`、`shared/src/schemas/`
- 验收：注册/登录/me 全流程 curl 通过；错误码语义一致；密码不落明文

### T2.3 鉴权中间件 + 数据隔离
- 内容：`requireAuth` 中间件解析会话并注入 `req.userId`；**所有业务路由强制鉴权**，所有 SQL 查询强制 `WHERE user_id = ?`；写操作强制写入当前 user_id（禁信客户端传入）
- 必读：`server/src/routes/*.ts`（全部）、`server/src/index.ts`
- 验收：无凭据访问业务 API 一律 401；A 用户无法读到 B 用户数据（构造两账号实测）

### T2.4 前端：登录/注册页 + useAuth 接通真实 API
- 内容：新增登录/注册页面（hash 路由如 `#/login`、`#/register`，视觉遵守极光玻璃 v2 + 令牌规范）；`useAuth` 改为调用 `GET /api/v1/auth/me`（**保持返回形状不变**，mock 逻辑删除）；landing 的登录/注册按钮（`TODO(账号系统)` 处）接到真实路由；登录后写凭据存储与 401 全局处理（`client/src/api/client.ts`）
- 必读：`client/src/hooks/useAuth.ts`、`client/src/App.tsx`、`client/src/components/landing/LandingNav.tsx`、`client/src/api/client.ts`、`交接文档/01-进度与上下文.md` §视觉规范
- 验收：未登录访问 `#/` 仍见 landing；注册→登录→进入 HomePage 全流程通；刷新保持登录；登出回到 landing

### T2.5 回归测试
- 内容：既有功能（番茄钟/森林/课程/任务/统计/预设）在登录态下全流程冒烟；landing 在真实未登录态下视觉回归（`e2e/verify-landing.mjs`）；构造双账号验证隔离
- 验收：lint + build 通过；冒烟无阻断问题；隔离实测通过

## 阶段 3：部署上线

### T3.1 服务器初始化
- 内容：Ubuntu/LTS 或 Debian；安装 Node LTS、MySQL 8、nginx；新建非 root 部署用户；防火墙只放 22/80/443
### T3.2 后端常驻
- 内容：PM2 托管 `server`（开机自启 `pm2 startup` + `pm2 save`）；`.env` 生产配置（强密码、生产数据库）；数据库初始化与迁移执行
### T3.3 前端托管与反代
- 内容：`client` 构建产物由 nginx 托管（gzip/brotli 开启）；`/api` 反代到 PM2 端口；静态资源缓存头
### T3.4 HTTPS 与域名
- 内容：DNS A 记录指向服务器；certbot（Let's Encrypt）签发并自动续期；强制跳转 HTTPS
### T3.5 安全与运维收尾
- 内容：CORS 收紧为精确域名（替换现通配）；安全响应头；数据库每日备份脚本（cron + 异地/对象存储可选）；日志轮转
### T3.6 备案与上线检查
- 内容：备案号填入 landing footer 占位 `.landing-footer__icp`（`TODO(上线)` 处）；对照 `.qoder/specs/滚动式介绍页设计.md` §8 上线前检查清单逐项打钩；生产环境全流程验收

## 子代理协作规则（主对话必须遵守）

1. **一任务一子代理**：每个 T 任务派发一个子代理，任务之间串行（T2.1→T2.2→…），T3 可酌情并行无依赖项
2. **子代理任务书必须包含**：目标、必读文件清单（上面的"必读"）、可修改范围、项目硬性约束（framer-motion 锁 11.18.2 / 动效 transform+opacity / 颜色用 CSS 令牌 / 禁改 git 配置与强制推送）、验收标准、要求返回的内容（改动文件清单 + 验证命令输出）
3. **主对话职责**：派发前向用户确认计划；子代理返回后亲自验收（跑 lint/build/实测命令，不轻信汇报）；验收不过则带具体错误重新派发
4. **禁止事项**：子代理不得执行 `git commit/push`（提交由主对话经用户同意后进行）；不得安装新依赖 unless 任务书明示；不得改动与任务无关的文件
5. 每完成一个 T 任务更新一次进度；阶段 2 全部完成后向用户汇报并等待阶段 3 启动指令
