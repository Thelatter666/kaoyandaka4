## 5. 我对计划做的一处偏离（必须知道）

计划 Task 4/5 原写的是 `surfaceRefs?: React.MutableRefObject<SVGElement[] | null>`，用回调 ref 收集元素数组。**我实现时改成了 `rootRef?: React.Ref<HTMLDivElement>`。**

原因：React 18 的回调 ref 在卸载时只收到 `null`，无法精确移除对应元素，数组会留下悬垂引用。改用根元素 ref + 让 `SmoothRing` 在 effect 里做一次 `querySelectorAll('.inkwell__surf-g, .inkwell__surf-clip')` 并缓存，更简单也更稳（`clipPath` 在 `<defs>` 内，同样能被查到）。

**所以 Task 5 里凡是写 `surfaceRefs` 的地方，都要按 `rootRef` 改写。** 建议的 `SmoothRing` 写法：

```tsx
const rootRef = useRef<HTMLDivElement>(null);
const surfEls = useRef<SVGElement[]>([]);

useEffect(() => {
  const root = rootRef.current;
  surfEls.current = root
    ? Array.from(root.querySelectorAll<SVGElement>('.inkwell__surf-g, .inkwell__surf-clip'))
    : [];
}, [mode, totalSeconds]);   // 波形变体切换会重建节点，需重查
```

rAF 内改写 `for (const el of surfEls.current) el.setAttribute('transform', tf);`。

计划文件本身**我没有回改**，以本节为准。

## 6. 四个「不要顺手改」的陷阱（都是原型阶段真踩过的）

| # | 陷阱 | 后果 | 出处 |
|---|---|---|---|
| 1 | `<clipPath>` 里套 `<g>` 承载平移 | `<g>` 是非法子元素 → 裁剪区为空 → **阳文被整体裁掉**。而 `getBBox()` 不受裁剪影响、读数完全正常，极易误判为「渲染正常」 | 组件注释 · spec §6.1 |
| 2 | `mask` 挂在被 `translate` 的组内 | mask 内容坐标随之偏移 → 挖空落到池外 → **阴文静默失效** | 同上 |
| 3 | 砚石纹进入中心文字安全区（`r < 104`） | 深斑点压在数字下 → **字糊成一团** | 同上 |
| 4 | 写成无限定的 `.inkwell__t-time { fill: ... }` | CSS 优先级高于呈现属性 → 染掉 mask 内的黑字 → **阴文挖空失效**。fill 规则**只能**写在 `.inkwell__relief` 之内 | 同上 |
| 5 | 把 `areaToHeight(f)` 简化成 `f` | 静默摧毁末段可读性，**且没有任何测试报错** | ADR-0003 |
| 6 | 给深色主题「补上」阴文 | 对比度打回 **1.96:1**（低于大字号 3:1 下限）。深色不做阴文是刻意的 | ADR-0004 |
| 7 | 注墨用 CSS `transition: transform` | rAF 每帧写 transform 会不断重启过渡 → 阻尼拖尾而非干净的 520ms 上升。必须在 rAF 内插值 | 计划 Task 5 |

陷阱 1/2/4 全是**静默失效**类 —— 不报错、不抛异常、测试全绿，只有肉眼看渲染才发现。所以 Task 5 里安排了一步「浏览器亲眼确认阴文真的挖出来了」，**别跳过它**。
