# 到点感知延迟 + 复盘上锁 + 关闭系统 — 设计文档

> 日期:2026-09-24 · 分支 `feat/lock-exit-and-timer-fixes` · 状态:已获用户批准并实施
> 需求原文(4 项,番茄钟 2 + 复盘 1 + 系统级 1):
> ① 倒计时结束后约 3 秒才播完成动画 ② 休息结束后应自动选中上一轮的预设
> ③ 复盘页解锁后要能在页面内重新上锁 ④ 顶栏最右上角加「关闭系统」按钮(确认后退出系统)

## 核心假设

- **A1**「关闭系统」= **停掉本地这套服务**(前端/后端进程 + 浏览器标签页),**不是登出**:服务端会话存 MySQL,重启后仍是登录态,下次双击 `~/Desktop/砚台考研打卡.command` 即可恢复。用户已确认。
- **A2** 关机能力只应存在于**本地启动脚本拉起的进程**里:部署在腾讯云的那份后端不得具备任何「关机」入口,能力边界靠「监听器进程是否被启动脚本拉起」划分,服务端零改动。
- **A3** 复盘「上锁」= 删解锁标记 + 回到验证态。解锁标记是**会话 cookie**(ADR-0005),跨标签页共享,所以上锁必须广播;又因为「关闭系统」只关标签页不关浏览器,会话 cookie 不会自然失效,**关闭系统必须显式清它**,否则「忘记手动上锁,系统退出后自动上锁」不成立。
- **A4** 会话自然到点的检测沿用既有惰性链(服务端/本地模式都在 `GET /focus/active` 里惰性自动完成),**不引入服务端定时器或后台任务**;只把「前端何时去问」从固定 10 秒轮询改成「到点即问 + 有界重试」。

## 显式权衡

- **W1** 到点校准放在客户端定时器里,而不是让服务端在 `planned_end_at` 时刻写库 —— 代价:客户端与服务端时钟偏差要靠重试覆盖(500ms × 12 ≈ 6s 窗口,超限回落 10 秒轮询)。换服务端零定时器、本地模式零改动。
- **W2** 关机走**独立监听器**(`scripts/local-power.mjs`,127.0.0.1:3999)而不是 Express 端点 —— 代价:多一个本机端口与一次跨域预检;换来线上后端完全不新增能力面,且本地能力随启动器进程一起消失。
- **W3** **不关终端窗口**(用户已同意) —— macOS 上程序化关窗不可靠:`shell 仍在运行时 Terminal 拒绝 `close``;shell 退出后窗口是否关闭取决于「当 shell 退出时」偏好(本机为默认的「不关闭」)。终端窗口保留并打印「已关闭系统」,由用户自行关窗;不做 UI 脚本(需辅助功能授权)或改全局偏好。

## 边界外声明

- 不做「关闭系统时自动登出」——用户明确要的是保持登录态(见 A1)
- 不做服务端关机端点、不做远程关机
- 不改 Terminal 全局偏好、不做 AppleScript 自动关窗
- 不做复盘锁重置/找回(沿 ADR-0005 边界)
- 不做到点校准的「提前预警」(如剩余 5 秒开始高频轮询)——按 plannedEndAt 精确排程已足够

---

## 1. 番茄钟:完成动画的 3 秒卡顿

**根因**:服务端的「过期自动完成」是惰性的,只在 `GET /focus/active` 被调用时落库(`server/src/routes/focus.ts` 的 `/active`;本地模式 `localStore.focus.getActive` 同构)。而前端只在两个时机调它:每 10 秒轮询、标签页从后台回前台。因此「墨面见底」到「发现会话已结束」要等下一次轮询到点(0~10 秒随机),之后才是 700ms 澄清动画。

**方案**(`client/src/hooks/useFocusSession.ts`):

- 新增**到点校准** effect:会话进行中且未暂停时,按 `plannedEndAt` 排一次定时器(首次 +250ms);返回仍是同一会话就每 500ms 重试,最多 12 次;超限回落 10 秒轮询兜底。
- 依赖只取会话的**标量字段**(`id`/`plannedEndAt`/`pausedAt`):轮询会把同一会话反复写回,若依赖整个对象,每次写回都会清掉重试链并把计数重置回 0。
- `probeActive` 区分「已无会话」与「请求失败」:失败按重试处理,不误判为结束。
- **顺带修一个潜在重复响铃**:`checkActive` 原先每次都 `setActiveSession(新对象)`,轮询会周期性换引用、重跑所有 `[activeSession]` effect;尾段高频拉取会把响铃 worker 的武装 effect 反复重跑,在客户端时钟快于服务端时**重复响铃**。改为内容未变(`sameSession`)就不换引用,同时也去掉每 10 秒一次的整页无谓重渲染。

**预期**:墨面见底 → 澄清开始 ≈ 一次请求往返 + 250ms;完成态 ≈ 1 秒内出现(其中 700ms 是澄清动画本身,属设计)。

## 2. 番茄钟:休息结束回到上一轮的预设

**根因**:`PomodoroPage.handleStartBreak` 显式 `setSelectedPreset(null)` —— 这是 2026-08-28 spec 写明的「行为不变项」(所有非「继续专注」入口一律清空),不是 bug。

**方案**:`handleStartBreak` 不再清空 `selectedPreset`(时长本就保留);「取消」「不休息」维持原样;同步修订 2026-08-28 spec 的该行。

## 3. 复盘:页面内上锁

- `utils/unlockMarker.ts` 增 `clearReviewUnlocked()`(`Max-Age=0` 删 cookie)与 `onReviewLocked()`(BroadcastChannel `kaoyandaily_review_lock`)。
- 新增 `components/review/ReviewLockContext.tsx`(149B 独立 chunk):门禁在已解锁态用 `<ReviewLockProvider value={lock}>` 包住 children,复盘页 `useReviewLock()` 取到回调才渲染按钮。**不从 ReviewGate 导出 context**:两者各自 lazy,跨模块引用会让复盘页 chunk 拖带门禁依赖(已用构建产物核对分包未退化)。
- `ReviewGate` 的 `lock()`:清标记 → 清空密码框 → 回验证态;并订阅其他标签页的上锁通知。
- `ReviewPage` 页头(PageShell `actions`)加「上锁」按钮:**有未保存修改时先确认**(复用页内既有的 dirty 确认模式),否则一点上锁正在写的内容就没了。

## 4. 系统级:关闭系统

**前端**(`client/src/components/layout/TopNav.tsx` + 新增 `utils/localPower.ts`):

- 按钮只在 `isLocalLauncherHost()`(`localhost` / `127.0.0.1`)时渲染——线上部署不显示,也没有任何可用端点。
- 点击 → `ConfirmDialog`(危险色)→ 确认后:**清复盘解锁标记** → `POST http://127.0.0.1:3999/power-off` → `window.close()`。
- 兜底:浏览器拒绝脚本关窗(非脚本打开的标签页)时,400ms 后渲染「系统已关闭 / 本页可以关闭了」全屏态;监听器不在(手动 `npm run dev`、线上、端口被占)时 toast 提示改关终端窗口。
- **按钮形态 = 44px 圆钮**(与主题切换/提示音开关同一造型),不带文字标签。首版带「关闭系统」文字标签时实测:导航胶囊 `max-width: 960px` 是既有设计,内容被撑到 973px,**在 ≥1024px 的任何窗口都恒定溢出 14px**(按钮挂在玻璃胶囊外)。改圆钮后内容 926px,各断点按钮右缘均落在胶囊内 9px。全称交给 `title` 与确认框。
- 连带把「≤1023px 隐藏导航文字」的断点从 960px 上移:带文字的自然宽度在 960px 视口只剩 2px 余量(邮箱前缀字符稍宽即溢出),提前收成图标留余量。

**监听器**(新增 `scripts/local-power.mjs`,仅由启动脚本拉起):

| 行为 | 说明 |
|---|---|
| 监听 | `127.0.0.1:3999`(外网不可达) |
| `OPTIONS` | 仅白名单 Origin(`http://localhost:5173` / `http://127.0.0.1:5173`)返回 204 + 许可头 |
| `POST /power-off` | 需白名单 Origin **且** 自定义头 `x-kaoyan-power: 1` → 200 `{ok:true}` → 200ms 后 `exit 0` |
| 其他 | 403 |
| 退出码 | `0` = 收到关机请求;`1` = 启动失败(启动脚本据此**保留服务**,不误拆) |

自定义头的作用是**强制 CORS 预检**:跨站页面无法用「简单请求」绕过预检直接打进来。

**启动脚本**(`~/Desktop/砚台考研打卡.command`,仓库外,已备份 `.bak`):

- 启动 `npm run dev` 与监听器两个进程,`trap INT TERM` → `stop_all()`(杀两个 PID + 释放 3001/5173/3999)。
- `while kill -0 $POWER_PID && kill -0 $DEV_PID; do sleep 1; done` 等待(不依赖 `wait -n`,兼容 macOS 自带 bash 3.2)。
- 监听器 `exit 0` → 走「已关闭系统」收尾并退出;`exit 1` 且 dev 仍在 → 打印提示并继续 `wait`(保留服务,退回「关窗口即停止」的老路)。
- 启动前顺带清理 3999 上残留的监听器。

## 错误处理

- 监听器端口被占 → 退出码 1 + 明确提示,启动脚本保留服务;前端 toast「无法关闭:本地启动器未在运行」
- 关机请求的网络/跨域失败(`fetch` reject 或非 2xx)→ 视为未关成,给 toast 而不清窗口
- 跨标签广播不可用(`BroadcastChannel` 缺失)→ 本标签页上锁仍生效,仅不向外传播

## 术语

| 术语 | 定稿含义 |
|---|---|
| 上锁 Lock | 页面内主动作废本次启动的解锁标记,使复盘重新需要密码;与「解锁」相对 |
| 关闭系统 Power Off | 停止本地前后端服务并关闭本页;不登出,下次双击启动脚本恢复且仍是登录态 |
| 本地关机监听器 Local Power Listener | 由启动脚本拉起的 127.0.0.1:3999 单端点进程,「关闭系统」的落地点;进程一死能力即消失 |
| 到点校准 End Sync | 会话 plannedEndAt 到点后立即拉取一次状态(失败按固定间隔有界重试)的机制,替代等下一次 10 秒轮询 |
