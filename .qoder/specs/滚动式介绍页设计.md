# 滚动式介绍页（Landing Page）设计文档

> 创建日期：2026-07-22
> 状态：设计已确认，待实施
> 关联：上线路线圈子项目 ①

---

## 1. 背景与目标

「砚台考研打卡」从「单用户本地工具」转型为「完全公开的产品」。滚动式介绍页是面向**未登录用户**的落地页，承担两个职责：

1. **转化**：向国内考研学生展示产品价值，引导注册
2. **门面**：作为上线后的首屏入口，建立品牌第一印象

### 成功标准

- 未登录用户访问根路径即可看到完整介绍页
- 滚动叙事流畅，动效在 `prefers-reduced-motion` 下完整降级
- 双主题（明/暗）视觉无损
- Lighthouse 性能分 ≥ 90

---

## 2. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 滚动动画 | **Framer Motion**（新增依赖，~30KB gzip） | `useScroll`/`useTransform`/`whileInView` 声明式 API；只操作 transform/opacity，符合项目动效规范 |
| 样式 | 现有 CSS 令牌体系 | 颜色禁止裸值，全部引用 `--color-*` 令牌 |
| 视觉风格 | 极光玻璃 v2 | 复用 `AuroraBackground`，与应用内体验一致 |
| 路由 | 复用现有 hash 路由 | 改动最小；history 迁移列为技术债（见 §8） |

---

## 3. 路由架构

**同一路由按登录状态分流**，不改动现有应用路由：

```
未登录：#/           → LandingPage（介绍页）
        #/plan 等    → 路由守卫重定向回 #/
已登录：#/           → HomePage（今日首页，现状不变）
        其他路由      → 现状不变
```

### 实现要点

- 新增 `useAuth` hook：调用 `GET /api/v1/auth/me` 判断登录态
  - 本阶段账号系统未开发，先提供 mock 实现：通过 `localStorage` 开关模拟登录/未登录两种状态（默认未登录），便于验收两条路由分支；接口上线后切换为真实实现
- [App.tsx](../../client/src/App.tsx) `renderPage` 增加守卫：未登录 + 非根路由 → 强制跳回 `#/`
- 介绍页自带极简顶部导航（logo + 登录/注册按钮），**不渲染应用 TopNav**
- 页面过渡：介绍页不参与现有 `.page-enter/.page-exit` 过渡（独立全屏体验）

## 5. 动效设计（Framer Motion）

**铁律：只动 `transform` 和 `opacity`**（项目动效规范），SVG `pathLength` 属绘制属性不涉及布局，允许使用。

| 位置 | 效果 | 实现 |
|---|---|---|
| S0 | 标题/副标题/按钮依次淡入上移 | `staggerChildren` + `opacity/translateY` |
| S0 | 滚动提示箭头呼吸浮动 | `animate: y: [0, 8, 0]` 循环 |
| S2-1 | 钉屏，圆环进度绑定滚动 | `sticky` 定位 + `useScroll` → `pathLength` |
| S2-2 | 树木生长 | `useScroll` → `scale + opacity` |
| S2-3/4 | 进度填充、逐条入场 | `whileInView` + `scaleX/opacity` |
| S3 | 数字滚动计数 | `useInView` + `animate()` |
| S4 | 多层视差 | `useTransform(scrollY)` → 不同速度 `translateY` |
| S5/S6 | 元素依次入场 | `whileInView` stagger |

### 无障碍降级

`prefers-reduced-motion: reduce` 时：所有滚动驱动动画禁用，内容以静态布局完整呈现（信息不丢失，仅无动效）。

## 6. 视觉与文案

- **风格**：极光玻璃 v2 完整延续；玻璃拟态卡片；双主题适配
- **颜色**：全部引用现有 CSS 令牌，禁止裸色值
- **字体/排版**：沿用现有 token 体系，大标题可用更大字阶（新增 `--text-hero` 令牌）
- **文案**：AI 撰写初稿（中文、克制、学生向），用户审阅定稿
- **截图（S4）**：开发完成后用 Playwright 截取真实页面，不使用设计稿冒充

## 7. SEO 与性能

- [index.html](../../client/index.html) 补齐：`title`、`description`、`keywords`、OG/Twitter Card 标签
- 语义化 HTML：`h1` 唯一、`section`/`nav`/`footer` 语义标签、`img` 必带 `alt`
- 性能：截图懒加载（`loading="lazy"`）；Framer Motion 按需打包（`LazyMotion` + `domAnimation`）
- **技术债**：hash 路由不利于 SEO，上线前迁移至 react-router history 模式（见 §8 阶段 2）

## 8. 上线路线图（全局视图）

本介绍页是三个子项目中的 ①，全局顺序：

### 阶段 0：启动备案（立即并行，不依赖代码）

1. 购买国内轻量云服务器（腾讯云/阿里云，2核2G，约 60-100 元/年）
2. 购买域名（约 55-70 元/年）
3. 提交 ICP 备案（云厂商代提交，免费，等待 1-3 周）

> 备案等待期正好用于开发阶段 1-2，时间不浪费。

### 阶段 1：滚动式介绍页（本文档）

依赖：无。登录态接口先 mock「未登录」。

### 阶段 2：账号系统 + 数据隔离（工作量最大，约占 60%）

- 新增 `users` 表；7 张业务表加 `user_id` 外键
- 注册/登录/会话管理（session cookie）；密码 bcrypt 哈希；登录速率限制
- 所有 API 查询按 `user_id` 过滤；Zod schema 同步更新
- 数据迁移脚本：现有本地数据归属到初始管理员账号
- 前端：登录/注册页、`useAuth` 接通、路由守卫生效
- 技术债：hash → react-router history 迁移（SEO 需要）

### 阶段 3：部署上线

1. 服务器初始化：Node.js 20、MySQL 8、nginx、PM2
2. 部署：`git clone` → `npm run build` → `npm run db:init` → 导入迁移数据
3. nginx：托管 `client/dist` 静态资源 + 反向代理 `/api` → `localhost:3001`
4. PM2 守护 Express 进程（开机自启 + 崩溃重启 + 日志）
5. HTTPS：certbot 申请 Let's Encrypt 免费证书
6. 域名解析 A 记录；footer 悬挂备案号（国内法规要求）
7. 安全收紧：CORS 白名单改为正式域名；生产 `.env` 独立管理
8. 运维：mysqldump 每日备份脚本（cron）；磁盘/内存监控告警
